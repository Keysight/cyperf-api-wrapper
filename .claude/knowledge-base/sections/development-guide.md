## Development Guide

### For AI Agents
- **Never hand-edit** files carrying the `"Generated by OpenAPI Generator... Do not edit"` header (all of `cyperf/api/`, `cyperf/models/`, `docs/`, and most of `cyperf/api_client.py`/`configuration.py`/`rest.py`/`exceptions.py`). The only files meant for direct edits are `cyperf/utils.py`, `cyperf/dynamic_model_meta.py`, targeted patches inside the "generated" core files (search for CyPerf-specific methods like `accept_eula`, `wait_for_controller_up`, `_get_access_token` to see the pattern), `samples/*.py`, `docker/Dockerfile`, `jenkins/JenkinsFile`.
- **There is no test suite to run.** `pytest --cov=cyperf` is wired into every CI config but collects zero tests — don't assume `pytest` output means anything passed/failed today. If asked to "run the tests," flag this gap rather than reporting a false green.
- Files named `test_*.py` under `cyperf/api/` and `cyperf/models/` are **not tests** — they're generated models/API classes for CyPerf domain objects literally named "Test..." (TestInfo, TestOperationsApi, TestUsage, etc.).
- Entry points for understanding real usage: read `samples/*.py` before `cyperf/api/*.py` — the samples show the two idiomatic call styles (raw `*Api` classes vs. `utils.TestRunner`). `cyperf/utils.py` and `cyperf/dynamic_model_meta.py` are the only two files with actual business logic to reason about; everything else is either generated plumbing or generated boilerplate.
- The `DynamicModel` layer is the trap most likely to confuse: a plain-looking attribute access on a model (e.g. `session.config`) can trigger a lazy **HTTP GET** under the hood if the field is link-backed and not yet loaded. `.update()` similarly can issue network calls. Don't assume model attribute access is side-effect-free.

### For Human Developers
- **Setup**: `pip install -r requirements.txt` (runtime) + `pip install -r test-requirements.txt` (dev tools); Python ≥3.8 (setup.py says `>=3.11`, pyproject.toml says `^3.8` — inconsistent, prefer 3.11+ to match CI's newer matrix legs).
- **Build**: `python setup.py install` or via Poetry (`pyproject.toml` present, but `setup.py` is what CI/Jenkins actually use).
- **Test**: `pytest --cov=cyperf` runs but exercises nothing (no test files exist yet).
- **Lint**: `flake8 . --max-complexity=10 --max-line-length=127` (CI, advisory) or `--max-line-length=150` (local `setup.cfg`); `mypy` configured but not enforced in CI.
- **Publish**: `jenkins/JenkinsFile` builds inside `docker/Dockerfile`, bumps `VERSION` via `sed`, and (if `publish_pypi=true` on a `release/` branch) publishes via `twine` using `.pypirc`. `publish.sh`/`git_push.sh` are local convenience scripts for the same flow.
- **Regenerating the client**: this repo is periodically re-synced against a newer CyPerf controller OpenAPI spec ("Re-generate wrapper" commits). After regenerating, re-apply the hand patches called out above (auth flow, EULA/controller-readiness helpers, `LinkNameException`, retry loop) since the generator will overwrite them.
