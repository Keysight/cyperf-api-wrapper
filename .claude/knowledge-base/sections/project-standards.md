### Architectural Rules
- Every generated file carries a `"Generated by OpenAPI Generator... Do not edit the class manually"` header — the implicit rule is: **hand edits are confined to `cyperf/utils.py`, `cyperf/dynamic_model_meta.py`, targeted patches inside `api_client.py`/`configuration.py`/`exceptions.py`, and `samples/`.** Regenerating the client (`.openapi-generator/FILES`, `.openapi-generator-ignore`) risks clobbering those hand patches unless they're re-applied or the generator is configured to skip them.
- All HTTP traffic funnels through one hub, `ApiClient.call_api` (via `RESTClientObject`) — no `*Api` class or model talks to `urllib3`/sockets directly.
- The `DynamicModel` metaclass layer depends on `cyperf/__init__.py` already having model classes bound (`get_inner_model` does `getattr(cyperf, name)`), and `cyperf/dynamic_models/__init__.py` depends on `DynamicModel` — a load-order coupling: `dynamic_model_meta` → `cyperf/__init__` (models) → `dynamic_models`.
